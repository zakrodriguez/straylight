## Answers

### Section 1

**Q1.** **Layer 4** (transport); it cannot route on **HTTP content** (URL,
host, headers) — only protocol/IP/port.

**Q2.** **Standard.** Any three: availability zones, an SLA, HA Ports, larger
backend pools, outbound rules, secure-by-default, backend pool by IP.

**Q3.** **c)** The frontend IP (public vs private).

**Q4.** It is **removed from rotation** automatically and re-added when it
recovers.

**Q5.** **False** — Standard LB backends have **no default outbound**; add an
outbound rule / NAT gateway / public IP.

**Q6.** **Load Balancer** — it's L4 and protocol-agnostic (any TCP/UDP port);
Application Gateway is HTTP/S only.

### Section 2

**Q7.** **URL path** and **host header** (also headers/cookies; TLS
termination) — invisible to L4.

**Q8.** A **frontend IP + frontend port + protocol** (HTTP/HTTPS).

**Q9.** **b)** The default backend pool.

**Q10.** App Gateway deploys its instances into the subnet and manages its IP
space; it must be **dedicated** (no other resources) to scale.

**Q11.** **Path-based**: one host, route by URL path. **Multi-site**: multiple
listeners by **host header** (different domains) on one gateway.

**Q12.** It is **long-running** (~15–20 min) — a lab step would hang past the
verification timeout; it's deployed by the topology and gated with
`az700.sh watch`.

### Section 3

**Q13.** **Application Gateway (WAF_v2)** and **Azure Front Door**.

**Q14.** The **OWASP Core Rule Set** (managed signatures); covers any two of:
SQL injection, XSS, RCE, protocol violations, etc.

**Q15.** **b)** Detection — log would-be blocks and clear false positives first.

**Q16.** Any two: add an **exclusion** for the tripping attribute; **disable
that specific rule** by ID; tune with a **custom rule**. (Not: disable the WAF.)

**Q17.** The **`ApplicationGatewayFirewallLog`** (diagnostic settings / Log
Analytics); you read it in **Detection** to remove false positives before
Prevention.

### Section 4

**Q18.** Via **DNS** (returns the chosen endpoint's address); it is **never on
the data path**.

**Q19.** Lowest latency → **Performance**; ordered failover → **Priority**;
split by percentage → **Weighted**; by region → **Geographic**.

**Q20.** **b)** DNS answers are cached until the TTL expires.

**Q21.** **Azure**, **external** (FQDN/IP), **nested** (another profile).

**Q22.** **Nested endpoints** (a parent profile pointing at child profiles).

**Q23.** **Traffic Manager = global**, **Load Balancer = regional**; the **Load
Balancer** is on the data path (Traffic Manager is DNS only).

### Section 5

**Q24.** A **global Layer-7 reverse proxy on the Microsoft edge** (TLS offload,
caching, WAF, origin routing at the nearest POP).

**Q25.** Any two: **edge caching**, **edge TLS termination**, **edge WAF**,
**global anycast** — App Gateway is regional and can't cache.

**Q26.** At the **Microsoft edge/POP** — bad requests are dropped **before
entering any region**, closer to the client, off-loading regional defenses.

**Q27.** (a) **Load Balancer**; (b) **Application Gateway**; (c) **Traffic
Manager**; (d) **Front Door**.

**Q28.** **Front Door** (global edge: entry, caching, WAF, TLS) → **Application
Gateway** (regional L7 URL-path routing + regional WAF) → **Load Balancer** (L4
to the VMs). (Traffic Manager appears where DNS-level cross-service routing is
also needed.)
